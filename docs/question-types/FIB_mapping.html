0. Key Transformation Rules

0.1 Type & SubType Mapping

Legacy type→ API type→ API subTypeNotes
FILL_IN_THE_BLANK FILL_IN_THE_BLANK BLANK_ON_TEXT (default hardcode) Type is a direct pass-through — no remapping. SubType is always BLANK_ON_TEXT.

0.2 Prompt Processing — sentence construction & @_@ replacement

Unlike MCQ/DnD, the entire body.prompt HTML goes into itemBody.sentence.text as-is. There is no split between statement and sentence. The only transformation applied to the prompt is replacing each <blank-field> tag with the @_@ marker.

Step 1 — Find all blank-field tags: Scan body.prompt HTML for all <blank-field id="N" ...>answer</blank-field> occurrences, in DOM order (top to bottom).
Step 2 — Replace each tag with @_@: Strip the entire tag including its content. Insert the literal string @_@ in its place. The correct answer text inside the tag is discarded here (it is captured separately in outcomeDeclaration.validation).
Step 3 — Image extraction: If the prompt contains a non-math <img>, extract it to itemBody.fibImage and remove the tag from the HTML. Same MathML detection rule as MCQ (§0.3 of main doc) — math SVGs stay as inline text.
Step 4 — Result → itemBody.sentence.text: The full modified HTML string (blank-fields replaced, image tag removed if extracted) becomes sentence.text.
Step 4 — itemBody.statement: Always set to { "content": { "type": "text", "text": "" } }. The prompt does not get split — statement is always empty.
Example:
Input: ...Mary and her friend <blank-field id="702" class="mceNonEditable">were</blank-field> going...
Output sentence.text: ...Mary and her friend @_@ going...

0.3 Blank ID Re-mapping (incremental)

The legacy <blank-field id="N"> attribute and body.blanks[].id use arbitrary integers. The QB FIBItem.id is reassigned as a sequential integer starting at 1, based on the order the <blank-field> tags appear in the prompt HTML.

AAT blank-field order in prompt→ QB items[].id→ QB correctAnswers[].blankId
1st <blank-field> tag (any AAT id)11
2nd <blank-field> tag22
Nth <blank-field> tagNN
Lookup bridge: To find a blank's data in body.blanks[], use the id attribute of the <blank-field> tag (e.g., 702) as a key to look up body.blanks[].id === 702. Then use the incremental QB id (e.g., 1) as the actual FIBItem.id and correctAnswers[].blankId. The AAT id is only used as the lookup bridge — it does not appear in the QB output.

0.4 Blank Weight Normalization

Legacy body.blanks[].weight is a percentage (100.0 for a single blank, 50.0+50.0 for two equal blanks). Normalize by dividing by 100.

Legacy blanks[].weight→ QB items[].weight
100.01.0
50.00.5
NN / 100

0.5 Answer Type Detection

The QB FIBItem.answerType is inferred from the text content inside the <blank-field> tag (the AAT correct answer preview).

Content of <blank-field>→ items[].answerType
Plain word or phrase (letters, spaces)"text"
Numeric value (digits, decimals)"number"
Fallback / unrecognised"text"

7. outcomeDeclaration Structure: FIB vs MCQ

MCQ outcomeDeclarationFIB outcomeDeclaration
 
outcomeDeclaration: {
  scoringType: ...,
  scoring: { ... },
  seeWhy: { ... },
  feedback: { ... },    ← optional
  validResponse: {      ← top level
    correctAnswers: [...]
  }
}
 
outcomeDeclaration: {
  scoringType: ...,
  scoring: { ... },
  seeWhy: { ... },
  feedback: { ... },    ← REQUIRED
  validation: {         ← extra wrapper
    scoringType: ...,   ← duplicated from outer
    validResponse: {    ← one level deeper
      correctAnswers: [...]
    }
  }
}
