0. Key Transformation Rules

0.1 Type & SubType Mapping

Legacy type→ API type→ API subTypeNotes
FILL_IN_THE_BLANK_DRAG_DROP DND BLANK_ON_QUESTION Type is remapped. SubType is always hardcoded — not auto-detected. All AAT DnD questions map to BLANK_ON_QUESTION during migration.
Available DnD subTypes in QB: BLANK_ON_QUESTION, TEXT_ON_IMAGE, BLANK_ON_SENTENCE, IMAGE_ON_IMAGE, IMAGE_ON_SPACE, IMAGE_TO_FIXED_1, IMAGE_TO_FIXED_2, SEQUENCE_IMAGE, SEQUENCE_TEXT, SPLIT_SCREEN. None except BLANK_ON_QUESTION are assigned during migration.

0.2 Prompt Processing — sentence construction & @_@ replacement

DnD processes body.prompt the same way as FIB — the full prompt HTML goes into itemBody.sentence.text with <blank-field> tags replaced by @_@. itemBody.statement is always null.

Step 1 — Find all blank-field tags: Scan body.prompt for all <blank-field id="N" ...></blank-field> tags in DOM order.
Step 2 — Replace each with @_@: Strip the entire tag and insert the literal string @_@ in its place.
Step 3 — Audio/Video extraction: Extracted <audio> → itemBody.audio. Extracted <video> → itemBody.video. Tags removed from the HTML.
Step 4 — Result → itemBody.sentence.text: The full modified HTML string becomes sentence.text. null if prompt is empty.
Step 5 — itemBody.statement: Always null. Prompt content goes into sentence.
Images in DnD prompt: Unlike FIB (which has a dedicated fibImage field), DnD has no equivalent. Prompt images stay embedded in the sentence.text HTML as-is — the <img> tag is not extracted. itemBody.image is always null.

0.3 Option Content Extraction — value vs answer

DnD uses .value, MCQ uses .answer. The choice item field name is different between types. Using the wrong field will silently produce empty options.
Question typeQB option idAAT id source (lookup only)Choice content field
MCQDirect from choiceItems[].choiceId—choiceItems[].answer
DnDIncremental (1, 2, 3…) by orderchoiceItems[].id used to resolve correctAnswers[].optionIdschoiceItems[].value

The DnD option content is parsed — media extracted, text cleaned — producing the same ContentItem array format as MCQ options.

3.3 itemBody.sentence — Sentence

The full body.prompt HTML with each <blank-field> tag replaced by @_@. Same approach as FIB.

API FieldTypeRequiredStatusLegacy AAT FieldNotes
itemBody.sentence SentenceTransform body.prompt null if prompt is empty/null.
itemBody.sentence.text StringYESTransform body.prompt Full prompt HTML with every <blank-field id="N" class="mceNonEditable"></blank-field> replaced by @_@. All other HTML (tables, images, spans, paragraphs) preserved as-is.

Example:
...using  <blank-field id="790" ...></blank-field> , avoiding...
→ ...using  @_@ , avoiding...

3.4 itemBody.targets[] — Target

One Target per <blank-field> tag found in the prompt, in DOM order. IDs are assigned incrementally (1, 2, 3…) — same rule as FIB items[]. The original AAT blank id is only used as a lookup key to pull weight data from body.blanks[].

API FieldTypeRequiredStatusLegacy AAT FieldNotes

itemBody.targets[].idIntegerYESTransform body.prompt (blank-field order) Incremental: first blank-field → 1, second → 2, etc. Not from blank-field[id] attribute. The original blank-field id attr is only used to look up the matching body.blanks[] entry for weight. Must match correctAnswers[].targetId.
itemBody.targets[].weightFloatYESTransform body.blanks[].weight Matched via blank-field id attr → body.blanks[].id. Normalize: divide by 100 (e.g. 100.0 → 1.0, 33.33 → 0.3333).

5.4 outcomeDeclaration.validResponse — DnDValidResponse

DnD validResponse is at the top level of outcomeDeclaration, same as MCQ. It is not nested inside a validation wrapper (that structure is FIB-only). DnD adds one field MCQ does not have: shouldAutoGraded.
