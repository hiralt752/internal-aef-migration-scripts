0. Key Transformation Rules

0.1 Type & SubType Mapping

Legacy type→ API type→ API subTypeNotes
IMAGE_LABELLING_DRAG_DROP DND BLANK_ON_QUESTION Type is remapped. SubType is always hardcoded to BLANK_ON_QUESTION — not auto-detected. All AAT Image Labelling DnD questions map to this subType during migration.
Available DnD subTypes in QB: BLANK_ON_QUESTION, TEXT_ON_IMAGE, BLANK_ON_SENTENCE, BLANK_ON_QUESTION, IMAGE_ON_SPACE, IMAGE_TO_FIXED_1, IMAGE_TO_FIXED_2, SEQUENCE_IMAGE, SEQUENCE_TEXT, SPLIT_SCREEN. Only BLANK_ON_QUESTION is assigned for this question type during migration. Other subTypes are not used.

0.2 Background Image Processing

Unlike standard DnD (which embeds images inline in sentence.text), Image Labelling DnD uses a dedicated itemBody.backgroundImage field. The source image URL is extracted from body.backgroundImage or the first <img> found in body.prompt.

Step 1 — Check body.backgroundImage: If present and non-empty, use directly as itemBody.backgroundImage.src.
Step 2 — Fallback to prompt: If body.backgroundImage is absent/null, scan body.prompt for the first <img src="..."> tag and extract its src as the background image URL.
Step 3 — Dimensions: Extract width and height from body.backgroundImage
Step 4 — itemBody.sentence and itemBody.statement: Both are always null. There is no text prompt for this question type — the image itself is the question.
No @_@ replacement: Unlike standard DnD, Image Labelling DnD does not use @_@ markers in a sentence. blank positions on the image are encoded in targets[].position using pixel coordinates instead.

0.3 Option Content Extraction — value vs answer

Image Labelling DnD uses .value, MCQ uses .answer. The choice item field name differs between types. Using the wrong field will silently produce empty options. This rule is identical to standard DnD.
Question typeQB option idAAT id source (lookup only)Choice content field
MCQDirect from choiceItems[].choiceId—choiceItems[].answer
DnD (BLANK_ON_QUESTION)Incremental (1, 2, 3…) by orderchoiceItems[].id used to resolve correctAnswers[].optionIdschoiceItems[].value
Image Labelling DnDIncremental (1, 2, 3…) by orderchoiceItems[].id used to resolve correctAnswers[].optionIdschoiceItems[].value

The Image Labelling DnD option content is parsed — media extracted, text cleaned — producing the same ContentItem array format as standard DnD options. Options may contain image URLs (draggable label images) or plain text labels.

3.5 itemBody.targets[] — Target

One Target per blanks defined in body.blanks[]. IDs are assigned incrementally (1, 2, 3…) in the order blanks appear in the legacy array — the same incremental rule as standard DnD targets[]. The original AAT blank id is used only as a lookup key to match weight and position data.

Coordinate system: blanks positions (x, y) are pixel offsets from the top-left corner of the background image. They must be within image bounds (0 ≤ x ≤ width, 0 ≤ y ≤ height). Values outside bounds should be clamped and flagged in the migration log.

5.4 outcomeDeclaration.validResponse — DnDValidResponse

Image Labelling DnD validResponse is at the top level of outcomeDeclaration, same as standard DnD and MCQ. It is not nested inside a validation wrapper (that structure is FIB-only). The structure is identical to standard DnD — shouldAutoGraded, correctAnswers[], and matchMode are all present.
