Asset upload and publish

3-step flow · Use your environment’s authoring-content-service base URL. API path: /api/assets

Step 1 — Get presigned upload URL

GET /api/assets/presigned-upload-url

Permission: CREATE on Asset module

Required query parameters

ParameterTypeExample
fileNamestringphoto.jpg
contentTypestringimage/jpeg
fileSizelong1048576

Response — save for steps 2 and 3

FieldUse
uploadIdRequired in step 3
fileIdRequired in step 3
presignedUrl.urlUpload target in step 2
presignedUrl.fieldsForm fields for step 2
 
GET /api/assets/presigned-upload-url?fileName=photo.jpg&contentType=image/jpeg&fileSize=1048576

Step 2 — Upload file to storage

POST to presignedUrl.url from step 1 (not the authoring service)

  • Content-Type: multipart/form-data
  • Add each item in presignedUrl.fields as form fields (key → value)
  • Add the file as the final form field (often file)

Upload must succeed (typically HTTP 204) before step 3.

Step 3 — Create and publish asset

POST /api/assets/create-and-publish

Permission: PUBLISH on Asset module

Required JSON body fields

FieldTypeSource
fileNamestringSame as step 1
fileIdUUIDStep 1 response
uploadIdstringStep 1 response
titlestringAsset title
descriptionstringAsset description
typestringe.g. IMAGE, VIDEO, PDF

Optional: altText, metadata, systemMetadata, tagIds (empty arrays are fine).

{
  "fileName": "photo.jpg",
  "fileId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "uploadId": "upload-abc-123",
  "title": "My asset",
  "description": "Short description",
  "type": "IMAGE",
  "metadata": [],
  "systemMetadata": [],
  "tagIds": []
}

Response (201 Created)

FieldDescription
assetIdCreated asset id
titlePublished version title
statusPublished status
createdAtCreation timestamp
contentPathContent path

Flow summary

  1. GET /presigned-upload-url → uploadId, fileId, presignedUrl
  2. POST file to presignedUrl.url using presignedUrl.fields
  3. POST /create-and-publish with uploadId, fileId, and asset metadata
